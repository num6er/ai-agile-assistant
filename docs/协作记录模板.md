## 四、协作方式说明

1. **代码管理**：使用 Git 进行版本控制，遵循 `CONTRIBUTING.md` 中的分支命名与提交信息规范（Conventional Commits）。

2. **分支策略**：`main` 为主分支并保持可运行状态，功能开发在 `feature/*`、`docs/*` 分支进行，通过 Pull Request 合入 `main`。

3. **代码评审**：周奕诺的改动均以 PR 形式提交，由郑磊 Review 代码差异后合并；合并时保留 Merge commit，以保留完整的提交历史与作者信息。

4. **任务分工**：
   - 郑磊负责后端整体架构（Flask 应用工厂、REST 蓝图、SQLAlchemy 模型、Service 层）、LLM 客户端与 Prompt 设计、核心算法（分批调用、跨批次负载均衡）、前端页面搭建与项目文档；
   - 周奕诺负责前端交互完善（任务看板状态筛选、Element Plus 中文化）、接口测试用例补充、LLM 调用重试机制、Docker 部署配置修复与运行时实测、常见问题文档。
   - 两人改动集中在不同目录与文件，后端接口约定后各自开发，避免了代码冲突。

5. **沟通方式**：通过聊天工具同步进度；交接时提供《项目进展与交接说明》与《队友协作手册》两份文档，明确环境搭建步骤与待办任务（见 `docs/` 目录）。

6. **CI/本地验证**：改动合并前在本地执行 `pytest` 与 `npm run build` 验证，确保 `main` 分支始终可运行。
